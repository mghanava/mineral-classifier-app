# M1.4 graph construction and leakage design

## Legacy production implementation

| Interface | Observed behavior |
| --- | --- |
| `construct_graph`, `prepare_edge_data` and `_create_graph_*` in [data_utils.py](../src/utilities/data_utils.py) | Connectivity uses Euclidean distance on supplied spatial coordinates. Feature scaling and labels do not select edges. The code builds the full pairwise distance matrix even for KNN, then selects the first configured rule in this order: KNN, percentile, fixed radius. Legacy YAML selected the fifth percentile, self-loops and min-max weights. |
| KNN | `KDTree.query` requests `k + 1` candidates per node. With self-loops enabled it retains every returned index. With loops disabled it drops the first result by position, assuming it is the querying node. Co-located points or distance ties can violate that assumption. There is no clamp for `k + 1 > N`. |
| Distance percentile | Calculates a separate percentile for each node across its distance row. The diagonal is replaced with infinity, which stays in the percentile input. A node selects all distances at or below its threshold. This is a per-node adaptive radius, and equal distances at the threshold can create more neighbors. With loops disabled it excludes all zero-distance pairs, including different samples at the same coordinates. |
| Fixed radius | Uses a strict cutoff `distance < radius`. With loops disabled it additionally excludes every zero-distance pair. Membership of a fixed pair is independent of other points when the radius and coordinate values are held fixed. |
| Symmetrization and edge payload | Appends reversals of all selected pairs without coalescing. A mutually selected pair appears twice in each direction, and each explicitly selected self-loop appears twice. There is no policy to reconnect isolates. The actual `edge_attr` is one float32 column, `1 / (distance + 1e-6)^2`. The helper docstring also mentions raw distances, which are not returned. |
| Splits and consumers | Bootstrap and next-cycle preparation construct a full graph before the stratified holdout and K-fold partitions are induced. `_create_subgraph` relabels endpoints and retains only edges internal to the selected nodes, along with their already computed attributes and weights. Prediction generation constructs a separate batch graph, using the prior base for synthetic sample generation. The legacy next-cycle stage used float32 coordinates for graph construction while storing canonical coordinates as float64. |

The current `normalize_edge_weight` applies min-max, standardization or softmax over the entire stored edge tensor. The extrema, mean and spread, or softmax denominator therefore depend on the graph population and edge multiplicity. A zero-distance loop produces an inverse-distance value near (10^{12}), which can dominate min-max scaling and push many off-diagonal weights toward zero. Standardization can produce negative weights and non-positive weighted degrees. Disabling weights yields `None`, which currently prevents the split branch from returning folds and conflicts with the GCN wrapper's weight requirement. `log1p` and the raw inverse-distance formula are edge-local. None of these edge transforms currently fits and persists parameters across graphs.

### What the models see

- **GCN.** [gcn.py](../src/models/gcn.py) passes `edge_weight` to each `GCNConv`. With the configured `normalize: true`, PyG applies weighted degree normalization to the supplied affinities. This is distinct from the builder's min-max operation, but both shape the effective weights. With layer self-loops enabled, the COO path keeps supplied loop weights and inserts the configured fill for missing loops. `improved: true` uses a fill of two for missing loops with supplied weights. It does not overwrite an existing normalized loop weight with two. Degree normalization remains graph-local and needs positive degrees for nodes with messages. The factory's normal configuration avoids the constructor's unsupported combination of layer-added loops and disabled normalization.
- **GAT.** [gat.py](../src/models/gat.py) passes `edge_attr` but creates `GATConv` without `edge_dim`. In installed PyG 2.8.0 there is no learned edge projection in this case, so varying the supplied inverse distance does not change the attention score at fixed node features and topology. GAT does not read `edge_weight`. It computes learned attention scores followed by a softmax over incoming edges, and duplicate non-loop edges still matter. With layer self-loops enabled it removes the input loops and inserts one per node. Enabling learned distance attributes would change the model and needs separate approval.
- **Fitted versus graph-local.** Model weights and any batch-normalization running statistics are learned on training graphs. The fold's feature scaler is fitted on its training rows and travels with the model. Spatial neighbor selection, local thresholds, edge-weight reductions, GCN degree normalization and attention coefficients are computed from the graph presented at the relevant stage under current rules. Graph-local operations become a leakage path when their graph includes held-out nodes. Layer-local normalization cannot undo topology or affinities already altered by those nodes.

### Confirmed effects and display mismatch

Small in-memory probes used unchanged functions with no self-loops. KNN with `k=1` and the fifth-percentile rule each connected training points at coordinates 0, 2 and 4 when built independently. After adding held-out points at 1 and 3 and inducing the training subgraph, both rules lost every training-to-training edge. Under radius 4, adding a disconnected pair at 100 and 100.25 changed the min-max weight of a retained distance-1 training edge from 1 to about 0.056. The pair had multiplicity two per direction. A separate two-node probe with `k=2` produced an out-of-bounds KDTree index. A PyG GAT forward probe also returned identical logits for different edge attributes with `edge_dim=None`.

`export_all_graphs_to_html` supplies the split coordinates to `export_graph_to_html`, which calls `prepare_edge_data` again. The figure draws the rebuilt edges but titles and statistics come from the stored graph. For adaptive methods these can be different edges. Density and degree use undirected formulas on the COO column count, which includes both directions, duplicates and loops. Plot colors also assume the labels present are contiguous from zero. [app.py](../app.py) discovers Plotly JSON and HTML in the data directories by filename and extension.

## Approved independent inductive protocol

Freeze membership before spatial graph construction. For each designated population, feed the same builder that population's ordered sample IDs and canonical float64 coordinates. Build independent graphs for each fold's train and validation set, calibration, test and each prediction batch. Keep the complete base as a raw population and optional explicitly labeled overview. It cannot provide edges or fitted graph statistics for model evaluation. Prefer raw spatial units with a documented coordinate metric and compatible units across axes. Keep model feature construction separate by applying the M1.3 fitted scaler only at the model input boundary.

| Decision | Recommendation and tradeoff |
| --- | --- |
| KNN | Select up to `min(k, N-1)` distinct non-self neighbors by distance, excluding the same sample ID explicitly and breaking ties by stable ID. Build the undirected union, with one COO entry per direction. Union preserves unilateral neighbor selections and can produce degree above `k`. Mutual KNN would reduce long bridges but creates more isolates. Report effective `k` and edge lengths, and consider a separately reviewed physical distance cap for sparse batches. |
| Fixed radius | Use a single positive, recorded radius in spatial units, retain the existing strict cutoff, and test boundary equality. Both dense clusters and sparse or isolated nodes are expected. A user-specified radius is a fixed rule. If a radius is estimated by a future protocol, estimate it only from designated training observations and freeze it for downstream graphs. |
| Distance percentile | Keep an explicitly named per-node, graph-local option for comparison. Compute the chosen quantile over finite distances to other sample IDs, removing the diagonal from the input entirely. Specify the interpolation method, tie handling and inclusive cutoff in the versioned rule. Do not replace this silently with a pooled global threshold. A training-derived fixed radius or quantile statistic is a different protocol and needs its own fit and artifact semantics. |
| Edge weights and normalization | Prefer non-negative per-edge affinities with an explicit scale in coordinate units. The bounded distance affinity is `1 / (1 + (distance / scale)^2)`, with a fixed configured scale and a finite output even at zero distance. Include unit weights as a baseline. Let GCN perform weighted degree normalization and leave GAT's topology-only path and per-neighborhood attention in place. Avoid graph-wide min-max, standardization and softmax as a default. If retained for experiments, version them as graph-local and reject incompatible signed GCN weights. Confirm any fitted affinity scale is learned from training only and then frozen. |
| Self-loops | The graph builder materializes exactly one loop per node when enabled. Use loop affinity 1.0 for standard GCN and 2.0 for improved GCN. Layer insertion will be disabled in production integration. Exclude loops from neighbor quotas and non-loop graph statistics. |
| Small graphs and isolates | Fail explicitly for an empty graph. For a singleton, keep the node, construct zero non-self edges and apply the declared loop policy. Keep isolates in all graph and result rows. Document the available self-information path when loops are disabled. Use correctly shaped empty arrays and reject unsupported training cases such as single-node training with batch normalization enabled. Allow distinct co-located sample IDs according to an explicit zero-distance policy, with bounded affinities and deterministic ties. |
| Graph visualization | Render the graph artifact's actual edges using its bound row order. Draw each undirected link once, display self-loop and isolate counts explicitly, and compute density and degree from unique non-loop links. Identify any overview as descriptive. Preserve Plotly filenames and formats. |
| Prediction batch size | Apply the same rules within each incoming batch, with no fallback to a historical context graph. Report node count, effective degree, isolates and edge-length summaries to expose sparsity or changes in prediction geometry. Independence is at graph level. A row can have different neighbors and logits when batched with different observations. Validate any production batching or minimum-size policy before deployment. |

The per-node percentile is a fraction of the possible neighbor count. With few ties and sufficiently large graphs, a fifth-percentile cutoff picks on the order of 50 candidates from 1,000 observations and 10 from 200 before symmetrization. Smaller fold and calibration graphs will also have different counts and radii. Compare degree and physical edge lengths across sizes and sampling densities before drawing conclusions from scores. **Recommend KNN as the candidate future default** after matched-split benchmarks for both models and a batch-size sensitivity check. A mostly fixed neighbor budget is easier to compare across batch sizes, while fixed radius is a stronger option when geological scales are meaningful. Production retains the fifth-percentile connectivity default.

**Spatial independence and spatial cross-validation answer different questions.** The protocol prevents held-out nodes from contributing to the training graph. The current stratified random splits can still place nearby or geologically related observations in different partitions. Claims about performance in geographically unseen regions need a spatial or grouped evaluation design with appropriate separation. Historical-context inference and transductive learning remain separate future protocols.

## M1.4-i standalone interfaces

- [`build_spatial_graph`](../src/utilities/spatial_graph.py) consumes only the designated population's canonical `float64` coordinates of shape `(N, 3)` and corresponding unique sample IDs. Supply exactly one of `k_nearest`, `connection_radius` or `distance_percentile`. It preserves input row order, excludes self by row identity during selection and builds an undirected union with one COO edge per direction. KNN uses a KDTree and resolves a boundary tie by stable ID after gathering all tied candidates. Fixed radius uses a strict comparison, and percentile uses NumPy linear interpolation after removing the diagonal, retaining all distances at or below the resulting per-node threshold.
- The output is a PyG `Data` with explicit `num_nodes`, preserved `sample_ids`, copied float64 `coordinates`, int64 `edge_index` of shape `(2, E)`, and float64 `edge_distance` of shape `(E,)`. `edge_weight` is float32 with shape `(E,)` and `edge_attr` contains that affinity as a single float32 column of shape `(E, 1)`. Coordinates and distances remain in physical coordinate units. `affinity_scale=None` supplies unit non-loop weights. A supplied positive scale selects inverse-quadratic affinity. `add_self_loops` and `loop_affinity` control the explicit loops. A zero-distance link between distinct samples has affinity one. Extreme but valid distances and scales can yield zero after float32 rounding.
- `summarize_graph` reports unique directed entries, including loops, and unique undirected non-loop links. Isolates are defined by non-loop degree, including a node with only a self-loop. Non-loop degree and physical length summaries report minimum, median, mean and maximum. Density is `2 * unique_non_loop_links / (N * (N - 1))`, with zero for a singleton. Edge length is absent when no non-loop link exists. Effective KNN quota is the requested `k` capped by `N - 1`, distinct from actual degree after symmetrization.
- The interfaces have no feature or label input. Production now feeds verified partition rows to this builder and prepares model features separately.

### Proposed synthetic affinity scale for integration

Start the integration comparison at **460 synthetic coordinate units**, subject to matched-split and prediction-batch sensitivity checks. The current generator samples a cylinder with radius 2,500 and depth 500, with minimum horizontal spacing of 10. A coordinate-only probe generated 1,000 base points with seed 110, used the first 467 as an illustrative fold-sized subset, and generated 200 incoming points with seed 111 while excluding base locations. Median selected non-self distances before symmetrization for the approved local fifth-percentile rule were about 458, 458 and 468 units respectively. The proposed scale gives a typical edge affinity near 0.5. The spacing of 10 is a horizontal exclusion floor and does not describe typical 3D link lengths. This is a fixed candidate for the synthetic domain, and the probe did not fit or persist a graph parameter. KNN or radius configurations should be checked against their own link-length distributions.

## M1.4-ii production integration

Bootstrap and next-cycle preparation verify stratified membership before building graphs. Each independent graph receives only its own rows in their existing order. Seeds and membership are preserved. The full-base graph is a descriptive dashboard overview. Prediction builds topology on the incoming observations alone. The synthetic generator still uses prior base locations for its original sample-exclusion rule, independent of the subsequent graph assembly.

All model graphs use canonical float64 XYZ values and Euclidean distances with unique reciprocal COO edges. Each model-neutral graph stores one loop of weight 1.0 when requested. At the model boundary, a clone receives the winning fold's frozen float32 feature transform and, for improved GCN, a weight of 2.0 on those stored loops. Both model constructors receive layer insertion disabled through the production entry points. GCN retains weighted degree normalization. GAT keeps its existing topology-only attention with no edge projection. Unit mode supplies weights of one to non-loop edges, while the same explicit loop policy applies. A singleton can be scored in evaluation mode. Training a singleton with batch normalization enabled raises an actionable error.

### Configuration migration

The shipped YAML keeps `data.base.distance_percentile: 5`, and selects `data.edge_affinity: {method: inverse_quadratic, scale: 460.0}`. Use `{method: unit, scale: null}` for the unit-weight baseline. Remove `data.make_edge_weight` and `data.make_edge_weight_method` completely from legacy files, even when set to null. Min-max, standardization, softmax, log scaling and unbounded inverse distance are outside the versioned protocol. Set exactly one of `k_nearest`, `connection_radius` and `distance_percentile`, and leave the other two null. Use top-level `add_self_loops` and keep `models.gcn.normalize: true`. Remove any model-specific `add_self_loops` override. These settings apply through the existing YAML workflow.

Regenerate independent graph artifacts and retrain/recalibrate in an isolated workspace before using pre-cutover outputs. The older weights, feature preprocessing, calibration and raw topology may have valid data within the previous protocol. They lack the graph binding this version requires. The app continues to use the existing graph, prediction and model paths.

### Artifact contracts and visualization

- Graph tensors carry a versioned protocol describing connectivity and parameters, coordinate dtype and metric, symmetrization, ties, affinity and the loop policy. The graph digest covers that metadata, dataset and split identity, row IDs, role, coordinates and exact edge tensors. Partition consumers also verify ordered raw rows and label alignment.
- The trained-cycle directory publishes `graph_binding.json` after `model.pt` and `preprocessing.json`. The graph binding records the model family, resolved graph settings, effective loop weight, selected training graph digest and exact weights and preprocessing digests. Evaluation checks the recorded training graph against the verified winning fold. Calibration bindings include the graph binding digest. Prediction must match protocol and effective model settings. Its topology and sample membership can differ, as can the independent calibration and test graphs.
- Plotly draws one segment per stored undirected non-loop link. Titles report actual unique links, directed edges, loops, isolates, non-loop degrees, density and physical edge lengths using `summarize_graph`. Labels and colors follow the class mapping even when classes are absent in a split. Existing HTML/JSON filenames and discovery conventions are retained. The new graph binding lives in the trained directory, outside the Plotly JSON glob.
- The DVC stage structure is preserved. Producers track graph settings and declare their Plotly outputs. Evaluation, prediction and drift track the graph binding as well as weights and preprocessing. Calibration binding continues to be covered by its evaluation directory output. Prediction graph generation does not depend on any fitted artifact. Graph-setting changes can regenerate raw observations because generation and graph assembly share stages. Scaler-only changes retain raw and graph production. A broader DVC audit belongs to M1.5.

### Verification and M1.4a handoff

The complete CPU suite passed 114 tests in 9.43 seconds. Tests preserve the pre-cutover stratified assignments, reconstruct model graphs locally, perturb held-out coordinates while checking fixed-model logits, verify weighted GCN normalization and GAT's topology-only behavior, exercise unit and singleton inputs, and reject stale/mismatched graph bindings. Plotly tests check stored links, diagnostic counts and non-contiguous labels. Generated DVC YAML matched the checked-in definition. A temporary DVC fixture verified independent scaler and graph-setting invalidation and graph-binding restoration. Full production reproduction and cache restoration remain unverified.

M1.4a should build a new graph from the verified full development population using this protocol, with no calibration or test rows. Fit a fresh preprocessing state on that population and agree on a fixed-duration schedule informed by cross-validation. Publish the refit graph, model and scaler provenance and recalibrate only on the independent calibration graph. Until then, the winning-fold checkpoint remains the production policy and uses only that fold's training subset.
