# M1.3 preprocessing architecture audit and design

## Pre-cutover lifecycle

Cycle N trains and evaluates against base cycle N−1. Paths below are relative to the repository root. This audit is based on source and pipeline definitions.

| Stage and entry point | Behavior and artifacts at M1.3a |
| --- | --- |
| Bootstrap, [generate_base_data.py](../src/stages/generate_base_data.py) `prepare_base_data` | `generate_mineral_data` returns coordinates, predictors, labels, hotspots and prototypes. Bootstrap passes a fresh configured scaler to `construct_graph`, which fits on the entire base feature matrix before extracting any split. Writes `results/data/base/cycle_0/{base_data,fold_data,test_data,calib_data}.pt`, `hotspots.npy`, `prototypes.npy` and diagnostics. |
| Graph and split, [data_utils.py](../src/utilities/data_utils.py) `construct_graph`, `_split_graph_no_leakage`, `_create_subgraph` | The full graph stores scaled predictors in `x` and copies the input predictors into `unscaled_features` as float32. It also stores coordinates and labels. The splitter first reserves a stratified holdout, divides it into test and calibration, then applies shuffled stratified K-fold splitting to the development pool. With current fractions, approximately 70% is development, 21% test and 9% calibration. Subgraphs copy rows of `x` and `y`, retain internal edges and relabel endpoints. They store `original_node_indices`, fold index and split type but omit raw features and coordinates. The split branch currently requires non-null edge weights. |
| Train, [train.py](../src/stages/train.py) `run_training` and [train_utils.py](../src/utilities/train_utils.py) `train` | Reads the prior cycle's `fold_data.pt`. Independent models consume the supplied `x` as-is. The lowest-validation-loss fold provides its best-epoch weights to `results/trained/cycle_N/model.pt`. No scaler or fitted feature schema is saved. The split graph's fold metadata is zero-based while the stage's diagnostics and selection log are one-based. |
| Evaluate and calibrate, [evaluate.py](../src/stages/evaluate.py) `run_evaluation` and [eval_utils.py](../src/utilities/eval_utils.py) `evaluate_with_calibration` | Load prior-cycle `test_data.pt` and `calib_data.pt` and current `model.pt`. Their `x` comes from the same pool-wide transform as the training graph. The model scores both graphs. `CalibrationPipeline` fits on calibration logits and labels and applies the calibrator to test logits. Writes `results/evaluation/cycle_N/calibrator.pt`, metrics and plots. The calibrator persists logit calibration state without the feature scaler or a binding to the originating checkpoint. |
| Generate prediction data, [generate_pred_data.py](../src/stages/generate_pred_data.py) `prepare_pred_data` | Loads prior base coordinates and bootstrap hotspots/prototypes. Generates synthetic features, coordinates and labels, then fits a fresh scaler on the new batch through `construct_graph(should_split=False)`. Writes both batch-scaled `x` and raw `unscaled_features` to `results/data/prediction/cycle_N/pred_data.pt` and exports graph diagnostics. |
| Predict, [predict.py](../src/stages/predict.py) `run_prediction` and [pred_utils.py](../src/utilities/pred_utils.py) `prediction` | Loads the current weights, prediction graph and calibrator, and uses batch-scaled `x` directly for calibrated and uncalibrated output. The utility sets graph labels aside before scoring, then uses synthetic ground truth to report supervised metrics. Outputs include `results/prediction/cycle_N/predictions.csv` and `metrics.json`. |
| Prepare the next cycle, [prepare_next_cycle_data.py](../src/stages/prepare_next_cycle_data.py) `combine_split_data` | Appends prior and new coordinates, `x` and synthetic labels, then calls `construct_graph(scaler=None)` and resplits the combined population. This carries forward earlier transforms alongside the new batch transform. The new `base_data.pt` copies that mixed matrix into both `x` and `unscaled_features`. The earlier partition assignments are not maintained as a longitudinal holdout. |
| Drift, [analyze_drift.py](../src/stages/analyze_drift.py) `run_analyze_drift` and [drift_detection_utils.py](../src/utilities/drift_detection_utils.py) `AnalyzeDrift` | Loads prior `base_data.pt` and current `pred_data.pt`. The median kernel-bandwidth heuristic, observed and permuted multivariate statistics, and pairwise/PCA displays use `x`. Marginal and distance plots use `unscaled_features`. The output is under `results/drift_analysis/cycle_N/`. From cycle 2 onward, the historical side's nominally raw field already contains a mixture of scaled blocks. |

`scaler_setup` in `data_utils.py` instantiates scikit-learn `RobustScaler`, `StandardScaler` or `MinMaxScaler` from `data.scaler_type` and `data.scaler_params`. The default YAML selects RobustScaler with the 25th and 75th percentiles. The helper converts a YAML quantile list to a tuple in the supplied config mapping. `scale_data` always calls `fit_transform`, including when passed an already fitted scaler. `construct_graph` also has a shared RobustScaler default instance, although all three pipeline callers pass a scaler or `None` explicitly. The exploratory `analyze_feature_discrimination` diagnostic separately fits a default RobustScaler on its input for silhouette/t-SNE plots. Its fit is not consumed by the classifier.

## Confirmed defects and scientific boundary

- **Preprocessing leakage.** In cycle 1 the full-base fit lets validation, calibration and test observations influence the representation used during training. Partition membership is established too late to protect the scaler fit. In later cycles, the untracked mix of earlier batch transforms also prevents identification of a single correctly fitted feature representation.
- **Training/inference mismatch.** Prediction batches fit their own location, spread or range parameters. The same raw row can therefore have different model features depending on the other rows in its batch. This undermines comparison of calibration and prediction probabilities. Independently centering or rescaling groups can also obscure distribution shifts or introduce apparent differences in drift statistics.
- **Raw values and identity.** Bootstrap and individual prediction artifacts retain pre-scaler values at float32 precision. Induced subgraphs have positional indices sufficient to gather those rows from the corresponding base artifact, provided the exact parent and row order are known. There is no persistent sample identifier or schema binding across files or cycles. Existing combined base artifacts cannot be trusted as raw input. Recovery requires trustworthy bootstrap and original prediction batches with known schema and ordering, or regeneration in an isolated workspace. Legacy checkpoints have no verified matching scaler.
- **Graph construction and leakage, M1.4.** Feature scalers do not act on spatial coordinates. `prepare_edge_data` uses Euclidean distances on raw coordinates, with precedence k-nearest, percentile, then fixed radius. The default percentile threshold is computed per node from the full base pool before subgraphs are induced. Full-pool k-nearest selection can also change which within-partition neighbors survive. Fixed-radius pair membership is coordinate-local, but min-max, standard and softmax edge-weight normalization use the constructed graph's edge population. Inducing a subgraph removes cross-partition edges while retaining the effects of these earlier calculations. Prediction builds a separate batch graph. Graph export recomputes displayed connectivity on the plotted subset, so a plot of a split can differ from the edges consumed by the model.

M1.3b can replace node features without rebuilding edges because the graph builder does not use predictor values to choose connectivity. The feature path can be verified independently with identical spatial inputs and partition indices. Carry forward the existing graph protocol as an explicitly identified limitation, and reserve claims of leakage-safe spatial evaluation for M1.4. If that review changes the graph protocol or partition contract, coordinate rollout of both changes before generating a new scientific baseline. Keep the current graph and feature artifacts compatible across all consumers at any runnable revision.

## Finalized standalone contract

M1.3b-i implements the contracts in [preprocessing.py](../src/utilities/preprocessing.py). M1.3b-ii uses them in the synthetic data, training, evaluation and prediction stages. Drift integration remains scheduled for M1.3b-iii.

- `RawDataset` holds a finite float64 feature matrix and three float64 coordinates per row. Labels, when present, are int64 indices into the ordered class-name tuple. Feature names, class names and sample IDs are unique and ordered. Immutable copies preserve canonical values and keep the dataset digest stable when caller-owned arrays change. The dataset SHA-256 covers schema, sample IDs, row order, raw numeric arrays and label presence and values. Arrays are encoded with their shape and little-endian float64 or int64 values in row order.
- `synthetic_sample_ids(batch_id, row_count)` derives `<batch_id>:<zero-based-row>` identifiers. The producers derive the batch ID from the generated feature, coordinate and label arrays and the source base digest or bootstrap marker. Identical content from the same source yields the same IDs, while different contents or sources distinguish batches. Carry the existing IDs forward when appending or selecting observations, and keep them separate from current parent row indices. A later cycle's identity must never replace an observation's original batch identity.
- `TrainingPartition` carries the exact parent digest, a **zero-based** fold index and immutable, unique, non-negative int64 training row indices. Its digest covers the parent, fold and ordered index vector. `fit_preprocessing` verifies the parent and index bounds and requires labels. The caller owns eligibility and split disjointness. The fitting function receives only the partition's training rows, even when validation, calibration or test rows are present in the parent. One-based fold labels can remain in existing plots and console messages.
- `FittedPreprocessing.transform` validates the input feature order, dimensions, canonical dtype and finite values, then returns a new float64 matrix. `transform_model_input` uses the same transform and casts to float32, rejecting overflow. Neither operation fits an estimator, mutates raw rows or touches graph edges. Training uses scikit-learn estimators configured with the existing constructor options, including YAML lists for ranges. `None` with empty options explicitly disables scaling.

### JSON sidecar v1

Keep `model.pt` as a weights-only state dict. Store `preprocessing.json` alongside it in the trained-cycle directory. Its top-level fields are `version` (integer `1`), `weights_sha256` (lowercase SHA-256 of the exact checkpoint file bytes), and `state`. The state requires every field below. Optional numeric values are written as JSON null.

| State fields | Meaning |
| --- | --- |
| `scaler_type` | `RobustScaler`, `StandardScaler`, `MinMaxScaler`, or null for identity. |
| `feature_names`, `class_names` | Exact column order and integer-label-to-class mapping. |
| `dataset_sha256`, `partition_sha256`, `fold_index` | Raw parent digest, training-partition digest and selected zero-based fold. |
| `center`, `scale` | For Standard and Robust, subtract the center and then divide by the scale. Each can independently be null. For MinMax, center is null and scale is a positive multiplier. |
| `offset`, `clip_bounds` | For MinMax, add the required offset after multiplying, then optionally clip at the two ordered bounds. Both fields are null for other variants. All numerical fields are null for identity. |

The format stores fitted transform coefficients and effective flags, including disabled centering or scaling and MinMax clipping. Fit-only settings such as the quantile range and execution options such as `copy` do not need to be replayed. Keep the resolved estimator and model configuration in the run configuration for reproducibility.

Load requires the expected feature and class schema and the weights file. It can also verify an expected training partition when that provenance is available. Missing, legacy, malformed and mismatched files raise an error. The JSON loader does not deserialize estimators or model weights. Digests verify consistency with expected files and are not signatures.

### Implemented integration contracts

| Boundary | Handling |
| --- | --- |
| Base and prediction graphs | Retain existing tensor paths. Full graphs carry `raw_schema_version=1`, the dataset digest, feature and class names, stable IDs, raw float64 `x` and coordinates, and int64 labels. The prediction artifact also records its source base digest. Model callers clone the verified graph and replace `x` with float32 model inputs. The presence of `unscaled_features` alone does not establish raw provenance. |
| Fold, calibration and test artifacts | Keep `fold_data.pt`, `calib_data.pt` and `test_data.pt`. Each split binds its role, fold and exact ordered parent indices to the dataset digest. Training and evaluation validate bounds, uniqueness, raw feature and label alignment, and disjointness of calibration, test and the development folds. |
| Model publication | Stage the winning fold's restored `model.pt` and fitted `preprocessing.json` in the output filesystem before replacing the final files, with the sidecar last. Consumers verify byte snapshots and load those same weights, so a partially published pair fails explicitly. Keep the winning-fold policy until M1.4a. |
| Calibration | Keep `calibrator.pt`, metrics and plots in the existing evaluation directory. Publish `calibration_binding.json` last. Its version 1 records `weights_sha256`, `preprocessing_sha256`, `calibrator_sha256`, `dataset_sha256` and `calibration_split_sha256`. Prediction verifies the binding and uses the exact verified calibrator bytes. This check is for trusted local artifacts and provides integrity, not authenticity. |

## Runtime handling

1. **Cross-validation.** Freeze partition membership before any scaler fit. For each fold, gather raw rows by its validated indices, instantiate a fresh scaler, fit only on the fold's training rows, and transform that fold's training and validation rows with the same fitted state. Supply temporary PyG model inputs with the original topology and labels. Publish the winner's preprocessing together with its restored best-epoch weights using the existing selection rule. Other folds' scalers can remain transient.
2. **Calibration and test.** Read the raw rows from the verified parent, verify and load the winning preprocessing, and transform both sets with that state. Fit probability calibration on the calibration logits only. Evaluate on the test logits with the fitted calibrator. Record the checkpoint pairing without changing calibration methods.
3. **Prediction.** Check that the synthetic batch's source base digest matches the model's training parent. Keep synthetic generation model-independent and persist raw observations and topology. At the scoring boundary, verify schema and model/calibrator pairing, transform once with the saved scaler, and use that same prepared graph for calibrated and uncalibrated scoring. Use synthetic truth only for diagnostics or explicitly authorized supervised cycle updates. General unlabeled inference is a later workflow.
4. **Next learning cycle.** Append canonical raw rows and corresponding coordinates, verified synthetic labels and persistent IDs. Validate feature/model-independent schema and provenance before merging. Repartition under the existing per-cycle policy and fit only when training the new model. Historical transformed values and model predictions never become raw observations or training labels. Fixed longitudinal holdout membership remains a separate decision. Treat pre-cutover metrics as historical and compare performance only across runs with a documented compatible protocol.
5. **Drift, pending.** During M1.3b-ii the drift stage exits with an actionable error before creating output. The dashboard's Drift tab and a full `dvc repro` therefore cannot complete successfully. Direct training, evaluation, prediction and next-cycle targets remain available with regenerated inputs in an isolated workspace. In M1.3b-iii, use canonical raw observations for marginal geological diagnostics. Use the same frozen model preprocessing for both reference and incoming observations in multivariate statistics, including the bandwidth heuristic and permutation samples. Record the feature space and checkpoint pairing in report metadata. Keep the current historical-base reference population unless a separate model-training reference policy is agreed. Drift describes a distribution change and does not establish a loss of predictive performance.

## DVC and dashboard impact

Training and evaluation track the raw parent and all split artifacts used to validate partition provenance. Evaluation and prediction track both model files, and prediction also tracks the exact calibrator and its binding. Raw generation is model-independent. The broader declarations below include follow-up work.

| Stage | Proposed declarations |

Broader artifact coverage can be reviewed in M1.5. Generate and validate candidate DAGs in temporary directories first, and leave production DVC cache/lock changes to an authorized run.

1. **M1.3b-i, complete.** Standalone tests compare the three scaler types and identity against scikit-learn or raw values, exercise JSON round trips and reject stale weights, malformed state and schema mismatches. They also check fit isolation, precision, raw immutability and batch-invariant row transforms.
2. **M1.3b-ii, complete.** Introduced versioned raw producers, index validation and raw next-cycle merging. Check preserved values and IDs over two cycles, unchanged coordinates and graph topology for identical inputs, and rejection of ambiguous legacy artifacts. Keep exploratory t-SNE fitting isolated from model training and label its scope.
3. **M1.3b-ii, complete.** Wired fold training, selection, evaluation and prediction as one compatible cutover. Use fixtures with shifted held-out features to check training-only fit statistics and verify that folds fit independently. Assert that winner and scaler IDs match even when a later fold loses. Assert that calibration, test and prediction use the saved transform and exercise fit-call guards in inference paths. Compare the transformed representation of one row across different prediction batches while holding topology out of that assertion.

Check that both sides and the bandwidth heuristic see the intended space and that a known raw shift survives, using small fixtures and a controlled statistic or permutation count. Verify DAG invalidation paths, declared artifact restoration and dashboard discovery with isolated fixtures. Real-data ingestion, graph protocol revision and full development-pool refitting belong to their scheduled work items.

## M1.3b-ii verification and compatibility

- Synthetic bootstrap and prediction producers preserve float64 values. For next-cycle graph construction and the generator's prior-coordinate exclusion, transient float32 coordinates preserve the previous numeric behavior. Canonical stored coordinates remain float64. Graph connectivity, normalization and the partition algorithm keep their existing implementation.
- Production feature discrimination plots now use raw observations to avoid an additional scaler fit in the generation stages. Their filenames and display paths are unchanged. For identity preprocessing, set `data.scaler_type` to YAML null and `data.scaler_params` to an empty mapping.
- CPU integration tests cover the real stage handoffs with deterministic synthetic arrays and two small folds, including the earlier-fold winner, exact weights and calibration binding failures, frozen features at both scoring paths, and a raw next-cycle merge. The real isotonic calibration and prediction utilities are exercised with a small model double. The existing independent-training test now uses versioned raw and split fixtures and checks disabled scaling.
- The complete CPU suite passed 51 tests in 3.17 seconds, including the 48 existing cases. Ruff lint and format checks and applicable pre-commit hooks passed.
- Generated DVC matched the checked-in definition, and DVC parsed the graph in a temporary repository. This verifies declarations and stage edges. Cache restoration and production reproduction remain pending.

## Open decisions and blockers

- Authorize a clean-workspace legacy cutover when ready to regenerate data and model/scaler/calibrator bundles. The existing DVC lockfile and real artifacts were left in place. Cached and historical outputs from before the cutover are not verified by the new contracts.
- Document drift reference membership and bandwidth units in M1.3b-iii. A fixed longitudinal holdout and stable external IDs require separate protocol decisions.
- M1.4 must settle inductive versus transductive construction, adaptive-neighbor and edge-weight statistics, and whether visualized edges should match model edges. Until then, corrected feature preprocessing alone cannot certify the spatial evaluation.
- M1.4a needs the final development population, graph and refit-duration rule. The same fitted-state contract can then describe the full-pool model instead of a winning fold.
